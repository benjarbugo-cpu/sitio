SITIO CAMARIN KAAGWASAN RICE MILL MANAGEMENT SYSTEM

Create a complete, modern, responsive Rice Mill Management System for Sitio Camarin, Barangay Kaagwasan, Dimataling, Zamboanga del Sur, Philippines. The system should be designed for actual rice-milling operations, inventory monitoring, farmer/customer records, milling transactions, payments, expenses, reports, and administrative management.

Build the application with a real database connection, but initially populate the system with realistic mock/demo data so every dashboard, table, chart, report, search, filter, and transaction can be demonstrated immediately.

1. System Name

SITIO CAMARIN RICE MILL MANAGEMENT SYSTEM

Subtitle:

Sitio Camarin, Barangay Kaagwasan, Dimataling, Zamboanga del Sur

Use a professional agricultural/rice-milling visual identity. The interface should use rice-inspired colors such as rice white, natural green, warm gold, and dark agricultural green, with excellent contrast and accessibility.

---

2. IMPORTANT ROLE SEPARATION

Implement strict Role-Based Access Control (RBAC).

There must be completely separate interfaces for:

ADMIN

Administrators can:

- Access the complete management system
- Manage farmers/customers
- Manage rice inventory
- Manage milling transactions
- Manage payments
- Manage expenses
- Manage employees/operators
- Manage equipment
- View reports
- Manage users
- Configure system settings
- View audit logs

CUSTOMER/FARMER

Customers/farmers must have a completely separate dashboard.

They can ONLY:

- View their profile
- View their rice-milling transactions
- View submitted rice batches
- View milling status
- View completed milling records
- View payments and balances
- View transaction history
- Download/print their own receipts
- Receive announcements/notifications

Customers MUST NOT be able to:

- Access Admin Dashboard
- Access Admin URLs/routes
- Manage users
- Modify inventory
- Modify milling rates
- View other customers
- View financial reports
- View employee records
- Access system settings
- Access audit logs
- Delete administrative records

Implement both frontend navigation restrictions and backend/server-side authorization.

Do NOT simply hide admin buttons. Unauthorized users must receive an Access Denied / 403 response when attempting to access protected routes directly.

Before completing the project, test every major workflow:

Login → Role Detection → Dashboard → Create Transaction → Rice Receiving → Weighing → Milling → Output → Payment → Inventory Update → Completion → Receipt → Report

Also test:

Customer Login → Customer Dashboard → Own Transactions Only → View Milling Status → View Payment → Print Receipt → Attempt Admin URL → 403 Access Denied

Make sure ADMIN and CUSTOMER/FARMER dashboards are completely separated both visually and technically, with proper route guards, API authorization, database ownership checks, and role-based navigation.
